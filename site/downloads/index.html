Program Guide

How each instrument fits.

Learn how each Open Source Food Truckin' feature lives inside the local program — the same teaching format as Open Source Barware’s program guide.

01 · Count · variance · order list · product master

Inventory sheets

The workbook view for every product, zone, PAR, pack, vendor, and Spanish name.

Inside the program this is Inventory sheets. Setup builds the first version from the approved truck map, then each cycle updates it with counts, invoices, and POS exports.

Looks like

  • Tabs: Count sheet, Variance, Order list, Product master
  • Rows by physical section: cooler, freezer, dry, prep, window, commissary
  • Columns for product, unit, pack, PAR, opening, purchases, closing, cost, variance

Process

  • Walk the truck by voice during setup.
  • The system turns that walk into the first map.
  • After you audit and approve it, the sheets become the weekly source of truth.

02 · Daily · weekly · monthly

Count types

Daily end-of-shift is a partial watch list. Weekly is the full truck. Monthly adds an extras checklist.

You pick the type and business date when you start a count. Crew logins can be limited to daily. A partial count only updates what it covers — everything else keeps its last count.

Looks like

  • Watch list by section, category, or picked products
  • History shows type, scope, and who counted
  • Weekly sales variance skips partials on purpose

Process

  • Set count types in Settings.
  • Start a count, walk the scope, complete it.
  • Read variance on the matching window.

03 · Mic or type · big −/+ steppers

Voice walk & count sheet

Speak the shelf in English or Spanish, check what it heard, save. On the phone, the count sheet is large taps, one-hand friendly.

The parser lives on your laptop. Firefox has no speech recognition — the typed box always works. Barcode scan needs Chrome.

Looks like

  • How-to-speak examples on the walk screen
  • Matched / which one? / not found review
  • Sticky Start / Complete bar on phones

Process

  • Walk each section in order.
  • Confirm heard lines.
  • Save; jump to variance.

04 · Square · Toast · Clover · any CSV

POS sales import

Upload a sales export. Format auto-detect, preview, then import. Generic column mapping for everything else.

Live POS APIs are documented stubs only. CSV column names come from public vendor docs and should be tested against your real file. Variance uses date-only matching.

Looks like

  • Preview before import
  • Voids skipped on Toast where documented
  • Clover exports with no dates: pick the sales date on import

Process

  • Export item sales from the POS.
  • Preview the mapping.
  • Import; theoretical usage = qty sold × recipe qty.

05 · Typed · CSV · PDF · photo

Invoices, receiving, optional photos

Log deliveries, match products, update cost. Snap invoice photos. Optional AI reading uses your own key and is off by default.

This is the only place AI ever enters the program. Skip it and type or paste — the local parser handles that on its own.

Looks like

  • Photo button labeled as needing AI
  • Type-or-paste sitting beside it as the default
  • Confirm line items before they touch the numbers

Process

  • Optional: add your own AI key in Settings.
  • Snap the Sysco / US Foods / local produce invoice.
  • Confirm; without a key, type or paste.

06 · Plate cost · PAR per stop · print tomorrow

Menu, stops, load lists

Cost every plate. Set pars for lunch lots, breweries, festivals. Print a load list before you roll.

Recipe qty must be in the product’s own unit (e.g. 0.04 pack of tortillas per taco). No unit conversion yet. Load list assumes on-hand is what’s on the truck.

Looks like

  • Food-cost % and margin per menu item
  • Stop types with their own PAR
  • Printable load list grouped for the next stop

Process

  • Build recipes from the catalog.
  • Name the stop types you actually work.
  • Print the list the night before.
